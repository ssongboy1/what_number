# 몇번인가요 (what_number)

음식이 나왔는데 몇 번 테이블 것인지 모를 때, **메뉴 이름으로 검색하면 그 메뉴를 주문한
테이블**이 바로 나옵니다. 포스에서 테이블을 하나씩 눌러볼 필요가 없습니다.

VD 포스는 주방 주문서를 인쇄할 때마다 그 내용을 PC 안의 기록 파일
(`kitchenPrinter_trace_날짜.log`)에 남깁니다. 이 프로그램은 그 파일을 옆에서 읽기만 합니다.
태블릿 오더로 들어온 주문도 똑같이 나옵니다.

```
[포스 PC] ──주방 주문서 인쇄──> [주방 프린터]
    └ 기록 파일 (포스가 원래 남기는 것)
         └ what_number.exe (읽기만 함)
              └── 검색 창
```

- **더블클릭하면 창이 하나 뜹니다.** 브라우저도, 인터넷도 필요 없습니다
- 포스 설정을 바꾸지 않습니다. 배선이나 추가 장비도 필요 없습니다
- **이 프로그램을 꺼도 포스와 주문서 인쇄에는 아무 영향이 없습니다** (읽기만 하므로)
- 취소된 메뉴는 검색에서 빠집니다

---

## 프로그램 받기

GitHub 에서 자동으로 만들어 둡니다. 직접 빌드할 필요가 없습니다.

1. [Actions 탭](https://github.com/ssongboy1/what_number/actions/workflows/build-exe.yml) 을 엽니다
2. 맨 위(가장 최근) 줄을 누릅니다 — 초록색 체크 표시가 있어야 합니다
3. 페이지 맨 아래 **Artifacts** 의 `what_number-exe` 를 눌러 받습니다
4. 받은 zip 을 풀면 `what_number.exe` 가 나옵니다

> zip 을 풀지 않고 그대로 실행하면 설정 파일이 저장되지 않습니다. 꼭 압축을 푸세요.

직접 만들고 싶으면 이 저장소를 내려받아 `build.bat` 을 실행하면 됩니다(파이썬 필요).

## 쓰는 법

### 1. 실행

`what_number.exe` 를 **포스 PC** 바탕화면에 두고 **더블클릭**합니다.

- "이 앱이 디바이스를 변경하도록 허용하시겠어요?" → **예**

**검색 창**이 뜹니다. 검은 창은 저절로 숨겨집니다.
창을 닫으면 프로그램이 꺼집니다. 포스에는 아무 영향이 없습니다.

### 2. 메뉴로 테이블 찾기

- 위쪽 칸에 **메뉴 이름 일부**를 칩니다 (예: `감바스`, `토마토`, 메뉴 번호 `34`)
  → 그 메뉴를 주문한 테이블이 최근 주문부터 나옵니다
- 칸 아래 **버튼**은 오늘 들어온 메뉴입니다. 누르면 바로 찾습니다
- 아무것도 치지 않으면 **최근 주문** 목록이 나옵니다
- **노란색 테이블 번호**는 20분 안에 들어온 주문입니다
- 취소된 메뉴는 **가운데 줄**이 그어져 나옵니다. 오른쪽 위 `취소 포함` 을 끄면 아예 숨깁니다
- 지우려면 `지우기` 버튼이나 `Esc` 키

### 3. 폰·태블릿에서도 보고 싶다면 (선택)

기본은 창 하나로 끝납니다. 폰에서도 보려면 이렇게 켭니다.

```
what_number.exe --web
```

이때만 검은 창에 폰용 주소(`http://192.168.0.15:8710`)가 뜨고, 윈도우 방화벽 창이 한 번
나옵니다(**액세스 허용**). 폰이 포스 PC 와 같은 와이파이에 있어야 합니다.

### 4. 매번 자동으로 켜지게 하려면

`what_number.exe` 바로가기를 만들어 아래 폴더에 넣어두면 부팅할 때 자동 실행됩니다.

```
Win + R  ->  shell:startup  ->  엔터
```

### "주방 기록 파일을 찾지 못했습니다" 가 뜰 때

프로그램은 `C:\PaLiDa` 안에서 기록 파일을 스스로 찾습니다. 다른 곳에 있으면 폴더를 알려주세요.

```
what_number.exe --log C:\PaLiDa\bin\log
```

매번 치기 번거로우면 exe 옆의 `config.json` 을 메모장으로 열어 `"kitchen_log_dir"` 에
그 폴더를 적어 두면 됩니다. (예: `"kitchen_log_dir": "C:\\PaLiDa\\bin\\log"`)

### 알아두실 것

- **주방 프린터와 연결되지 않은 메뉴는 나오지 않습니다.** 주방 주문서가 인쇄되지 않으면
  기록도 남지 않기 때문입니다. (예: 시험해 본 "투쁠원 위크" 세트는 주방 주문서가 나가지 않았습니다)
- 주문 기록은 이 PC 에만 저장되고, 48시간이 지나면 자동으로 지웁니다.

# 참고: 주방 기록 파일이 없는 포스에서 쓰는 법

아래는 VD 포스가 아니거나 주방 기록 파일이 없는 포스를 위한 예전 방식입니다.

## 포스가 주문을 어디에 저장하는지 찾기 (변화찾기)

포스 프로그램은 주문이 들어오면 그 내용을 PC 안의 파일에 적어 둡니다. 주문을 넣는
순간 어떤 파일이 바뀌는지 지켜봐서 그 파일을 찾아냅니다. **읽기만 하고**, 포스 설정이나
파일은 건드리지 않습니다. 영업이 한가할 때나 영업 전후에 하는 것을 권합니다.

1. `what_number.exe` 를 **포스 PC** 에 복사합니다. 포스 프로그램은 켜 둔 채로 둡니다
2. exe 가 있는 폴더를 열고, 위쪽 주소창을 누른 뒤 `cmd` 라고 치고 엔터
3. 검은 창에 아래를 입력하고 엔터

   ```
   what_number.exe --changes
   ```

   포스 폴더를 알고 있으면 뒤에 붙여도 됩니다. 예: `what_number.exe --changes C:\Palida`
4. 포스에서 **주문을 한 건 넣고**, 곧바로 검은 창을 한 번 누른 뒤 **엔터**
5. 4번을 두세 번 되풀이합니다
6. `끝` 이라고 치고 엔터

끝나면 `data\변화찾기_날짜.zip` 파일이 생깁니다. **이 zip 파일 하나를 보내주세요.**
결과 글과, 주문 파일로 보이는 것들의 복사본이 들어 있습니다.

> 복사본에는 매장 주문 기록이 그대로 들어 있습니다. 믿을 수 있는 곳에만 보내세요.
> 결과는 30초마다 저장되므로 도중에 창을 닫아도 `data\변화찾기_날짜.txt` 는 남습니다.
> 30분이 지나면 저절로 끝납니다.

## 잘 안 될 때

### 먼저: 프린터가 어디로 주문서를 보내는지 찾기

포트를 추측하는 대신 직접 찾아냅니다. 모든 통신을 잠시 지켜보다가 주문서처럼
생긴 데이터가 어디로 가는지 알려줍니다. 지켜보기만 하고 아무것도 보내지 않습니다.

```
what_number.exe --scan
```

실행하면 3분간 지켜봅니다. 그동안 **포스에서 주문을 한 건 넣어주세요.**
★ 표시된 곳이 프린터입니다. 아무것도 안 잡히면 프린터가 시리얼(COM) 연결입니다.

### 프린터 연결 방식 확인하기

명령 프롬프트에서 아래를 실행하면 이 PC 의 프린터 연결 방식과 주문 데이터 위치를
조사해 `data\진단결과_*.txt` 로 저장합니다. 읽기만 하고 아무것도 바꾸지 않습니다.

```
what_number.exe --diagnose
```

프린터가 시리얼(COM) 연결이면 이 프로그램의 감시 방식으로는 잡히지 않으므로,
먼저 이것부터 확인하는 편이 빠릅니다.

### 주문을 넣어도 화면에 아무것도 안 뜬다

1. 검은 창에 `! ` 로 시작하는 줄이 있는지 봅니다. 있으면 그 내용이 원인입니다.
2. 프린터가 **랜선으로 연결**되어 있는지 확인합니다.
   USB로 연결된 프린터는 이 방식으로 볼 수 없습니다.
3. 포스가 쓰는 포트가 다를 수 있습니다. `config.json` 의 `printer_ports` 에
   포트를 추가해 보세요. (기본값: 9100, 9101, 9102, 515)
4. 포스 PC가 아닌 다른 PC에서 실행하면 아무것도 안 잡힙니다.
   반드시 **주문을 받는 포스 PC**에서 실행해야 합니다.

### 테이블 번호가 "번호 미확인" 으로 나온다

전표의 테이블 표기 방식이 기본 인식 규칙과 다른 경우입니다.
주문 카드를 눌러 원본을 보면 실제로 어떻게 찍히는지 알 수 있고,
`config.json` 의 `table_patterns` 에 규칙을 추가하면 됩니다.

`data\dumps` 폴더에 최근 인쇄 원본이 자동으로 저장되니, 그 파일을 보내주시면
규칙을 맞춰 드릴 수 있습니다.

### "이 주문서는 이미지로 전송되어 글자를 읽을 수 없습니다"

포스가 주문서를 글자가 아닌 **그림으로 그려서** 프린터에 보내는 방식입니다.
이 경우 글자를 읽어낼 수 없어 별도 작업(이미지 복원 + 문자 인식)이 필요합니다.

### 백신이 프로그램을 막는다

패킷을 들여다보는 동작 때문에 일부 백신이 의심스럽게 볼 수 있습니다.
백신의 예외(허용) 목록에 `what_number.exe` 를 추가하세요.

## 설정 바꾸기

exe 를 한 번 실행하면 옆에 `config.json` 이 생깁니다. 메모장으로 열어 고친 뒤
프로그램을 다시 켜면 적용됩니다.

| 항목 | 설명 | 기본값 |
|---|---|---|
| `web_port` | 화면 주소의 포트 번호 | `8710` |
| `kitchen_log_dir` | 포스 주방 기록 폴더. 비우면 `C:\PaLiDa` 안에서 찾음 | `""` |
| `printer_ports` | 감시할 프린터 포트 | `[9100, 9101, 9102, 515]` |
| `retention_hours` | 주문 기록 보관 시간 | `48` |
| `idle_seconds` | 이 시간만큼 조용하면 한 장이 끝난 것으로 봄 | `2.0` |
| `encoding` | 글자 인코딩. 비우면 자동 판별 | `""` |
| `open_browser` | 시작할 때 브라우저 자동 열기 | `true` |
| `table_patterns` | 테이블 번호 인식 규칙 (정규식) | 아래 참고 |

`table_patterns` 는 목록 위쪽에 있는 규칙이 먼저 적용됩니다. 각 규칙은 숫자
한 개를 괄호로 잡아야 합니다. 예를 들어 전표에 `[ 8 번 ]` 처럼 찍힌다면
`"\\[\\s*(\\d{1,3})\\s*번"` 을 목록 맨 앞에 넣으면 됩니다.

## 알아둘 점 (프린터 감시 방식)

- **주문 취소·수정은 반영되지 않습니다.** 프린터로 나간 주문서만 보는 구조라,
  포스에서 취소한 주문도 목록에는 남아 있습니다. "방금 뭐가 나갔는지" 확인하는
  용도로 쓰세요.
- **전표에 개인정보가 있을 수 있습니다.** 배달 주문서에는 전화번호와 주소가
  찍힙니다. 그래서 기록은 기본 48시간만 보관하고 자동으로 지웁니다.
  `retention_hours` 로 더 짧게 줄일 수 있습니다.
- 같은 주문서가 주방·바 등 여러 프린터로 나가도 목록에는 **한 건**으로 묶입니다.

## 개발자용

외부 패키지 없이 파이썬 표준 라이브러리만 사용합니다.

```bash
# 테스트
PYTHONPATH=src python -m unittest discover -s tests

# 포스 없이 화면만 확인 (가짜 주문 8건)
PYTHONPATH=src python -m what_number --demo

# 저장된 인쇄 원본으로 인식 결과 확인
PYTHONPATH=src python -m what_number --replay data/dumps/*.bin

# exe 만들기 (윈도우)
build.bat
```

### 구성

| 파일 | 역할 |
|---|---|
| `kitchen_log.py` | VD 포스 주방 기록을 따라 읽고 주문서를 해석한다 (지금 쓰는 방식) |
| `menu_store.py` | 메뉴·테이블 저장, 프린터별 중복 묶기, 취소 반영, 메뉴 검색 |
| `search_web.py` | 메뉴로 테이블 찾기 화면 |
| `sniffer.py` | 윈도우 raw socket(SIO_RCVALL)으로 패킷을 읽는다 |
| `reassembly.py` | TCP 조각을 모아 전표 한 장 단위로 되돌린다 |
| `escpos.py` | ESC/POS 제어 명령을 걷어내고 글자만 남긴다 |
| `orders.py` | 전표 글자에서 테이블 번호·항목을 뽑는다 |
| `store.py` | SQLite 저장, 중복 묶기, 오래된 기록 정리 |
| `web.py` | 주문 화면과 조회 API |
| `app.py` | 위 조각들을 하나로 엮고 실행한다 |
